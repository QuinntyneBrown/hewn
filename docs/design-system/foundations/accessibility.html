Accessibility

Hewn meets WCAG 2.2 AA on every page in every state, in both themes, by keyboard alone. These are the commitments every component makes and how they are checked.

Overview

Requirement L2-047 sets the bar: axe-core finds no serious or critical violations on any page in any state, everything is reachable and usable by keyboard with a visible focus indicator and no traps, and stage status changes are announced politely at most once every 5 seconds per project. L2-048 adds 4.5:1 text contrast in both themes; L2-046 adds no horizontal scroll from 320 to 2560px.

Perceivable

Non-text contrast1.4.11Control edges (--color-border-strong), meaningful icons, pipeline and meter fills, and the focus ring ≥ 3:1 against neighbours. Hairlines between content are decorative and exempt.

Non-text content1.1.1Decorative SVGs are aria-hidden; icon-only controls have aria-label; the design preview frame and video have titles; the pipeline strip has a text alternative.

Focus ring

One ring for everything focusable: outline: var(--focus-ring-width) solid var(--color-focus-ring); outline-offset: var(--focus-ring-offset) on :focus-visible. The offset gap shows the surface, so the ring passes 3:1 against both a blue primary button and the page. Where an outline would be clipped, the same ring is drawn with --shadow-focus (see Elevation).

TokenValueUse
--target-minSmallest target (WCAG 2.5.8).
--target-comfortableTouch target below lg: nav links, tabs, icon buttons.

L2-046 AC4 asks for touch targets of at least 44×44px below 992px and 24×24px from 992px (ADR 0034). Below lg every control is 44px; from lg, buttons and rows use 32–40px control heights, which meet WCAG 2.5.8 (24px) for pointer use. Control heights are on Spacing.

Component contract

Every component page's Accessibility section answers the same seven questions, so a reviewer can check any component the same way:

  1. Role and pattern: the native element or WAI-ARIA APG pattern, linked.
  2. Keyboard: a table of keys and what they do.
  3. Focus: where focus starts, where it goes on close, what the ring looks like.
  4. Labelling: what needs a name, how it gets one, what is announced.
  5. Contrast: the token pairs involved, with live ratios in both themes.
  6. Motion: what animates and what happens under reduced motion.
  7. Touch: target sizes and the alternative to any hover-only affordance.

Usage

  • Use the native element. A div with a click handler is a bug, not a variant.
  • Do not remove the focus outline; if a design hides it, the design is wrong.
  • Hide owner-only actions from Viewers instead of disabling them, and say why where it matters (Read-only for Viewers).
  • Every new colour pairing is added to contrast-pairs.json before it ships.
  • Live updates go through the one status announcer, not ad hoc aria-live regions per component.
