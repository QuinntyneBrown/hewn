Theming

Light and dark are two values for the same semantic tokens. The OS decides until the person chooses; components never know which theme they are in.

WCAG 2.2 AA

Overview

  • A theme overrides colour and shadow tokens only (82 tokens). Type, space, layout, shape, motion and z-order are the same in every theme.
  • Light is :root. Dark is [data-theme="dark"] and, with no attribute, the OS preference. Light is restated under [data-theme="light"] so it can be forced, and so a light island inside a dark page works.
  • Each theme sets color-scheme, so native scrollbars, form controls and the date picker follow.
  • Dark carries the prototype's palette; light is derived from the same roles and verified separately. Neither is an inversion of the other.

How it works

/* tokens.css (generated from _build/tokens.py) */
:root {                                   /* light is the default */
  --color-bg-canvas: var(--palette-stone-100);
  …
  color-scheme: light;
}
[data-theme="light"] { …same light values… }   /* restated, so a light island works inside a dark page */
[data-theme="dark"]  { --color-bg-canvas: var(--palette-slate-950); … color-scheme: dark; }
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { …identical to [data-theme="dark"]… }
}

The choice is made in Settings → Appearance (pages/settings/default (Light, Dark, System)), applies immediately, is kept in localStorage['hewn.theme'] on this device, and survives reloads (L2-048 AC2). Viewers can change their own theme and nothing else. Keep the two dark blocks identical: the generator writes both from the same data, and check_contrast.py reads both.

Islands

Any element can set data-theme to render its subtree in another theme: these docs use it for the side-by-side examples. In the product the increment video and design preview do not need an island: they use the fixed --color-preview-* tokens instead, because they draw the customer's app, not Mission Control.

An island must set color and background itself. Tokens re-resolve inside the island, but properties the parent already computed (its text colour) inherit as finished values. A brand change touches primitives; changing what accent means touches semantic tokens; changing how buttons look touches component tokens. Each change lives in exactly one tier.

Adding a theme

  • Add primitives for any new hue to PALETTE in _build/tokens.py.
  • Add a theme block that sets every --color-* role and the five shadow tokens, plus color-scheme. Start by copying the light or dark column; change roles, never names.
  • Add the theme to the contrast checks and run check_contrast.py until every pair passes.
  • Add the option to Settings → Appearance and to ThemeChoice; the service only sets the attribute.
  • Screenshot the mocks and these docs with ?theme=<name>.
  • See Color → Adding a brand theme for the accent set to override.

Contrast and forced colours

  • prefers-contrast: more applies in every theme: hairlines take --color-border-strong and subtle text takes --color-fg-muted.
  • forced-colors: active: the focus ring becomes Highlight and borders CanvasText; everything else is left to the system palette. Edges drawn as inset box shadows disappear in forced colours, so controls whose edge matters also keep a transparent outline or border.
  • Print uses light regardless of the theme.

Using tokens in Angular

Mission Control is Angular. It ships the two stylesheets as global styles and reads tokens in component styles as plain var(--…); it never redeclares a token value.

// angular.json → projects.mission-control.architect.build.options
"styles": [
  "src/styles/tokens.css",        // copied from docs/design-system/tokens/tokens.css
  "src/styles/components.css",    // copied from docs/design-system/assets/components.css
  "src/styles.css"
]
// mission-control/src/app/core/theme.service.ts
@Injectable({ providedIn: 'root' })
export class ThemeService {
  private readonly key = 'hewn.theme';               // 'light' | 'dark' | 'system'
  readonly choice = signal<ThemeChoice>(this.read());

  constructor() {
    effect(() => {
      const c = this.choice();
      const root = document.documentElement;
      if (c === 'system') root.removeAttribute('data-theme');   // CSS follows prefers-color-scheme
      else root.setAttribute('data-theme', c);
      try { localStorage.setItem(this.key, c); } catch { /* private mode: keep in memory */ }
    });
  }
  private read(): ThemeChoice {
    try { return (localStorage.getItem(this.key) as ThemeChoice) ?? 'system'; } catch { return 'system'; }
  }
}

For values TypeScript needs (breakpoints for BreakpointService's matchMedia queries, durations for timers, chart colours), generate constants from tokens/tokens.json, the W3C DTCG export. Aliases are {group.token}; each token carries its CSS name and its dark value under $extensions:

{
  "color": { "bg": { "canvas": {
    "$type": "color",
    "$value": "{palette.stone.100}",
    "$extensions": { "com.agent-toolkit": {
      "css": "--color-bg-canvas",
      "themes": { "dark": { "$value": "{palette.slate.950}" } }
    } }
  } } }
}
  • Generate at build time (a small Node script or Style Dictionary) into src/app/core/tokens.ts; do not hand-copy values.
  • Read colours at runtime with getComputedStyle(root) + .getPropertyValue('--color-accent') when a canvas or chart needs them, and re-read on theme change; generated constants hold only the light value.
  • Never put a token value in a component's styles; if a component needs a new value, it is a new token in tokens.py.

Usage

  • Write components against roles and test them in both themes; a component that looks right in only one is using the wrong role.
  • Do not branch on theme in code (if (dark)). If something must differ, it is a token with two values.
  • Do not use prefers-color-scheme in component CSS; only tokens.css reads it.
  • Islands are for documentation and genuine embeds. Product surfaces that must look fixed use fixed tokens (--color-preview-*, --color-bg-scrim).
  • Images and screenshots of the product being built are shown as they are; do not invert or dim them in dark.

Accessibility

  • Both themes meet WCAG 2.2 AA on every declared pair (L2-048 AC2 asks for 4.5:1 text in both); see Color → Contrast pairs.
  • The theme follows the OS by default, which respects people who set dark mode for light sensitivity, and the choice is per device.
  • The theme toggle in Settings is a radio group with visible labels and descriptions (Follow your operating system), not an icon-only switch.
  • Changing theme moves nothing and announces nothing; focus stays where it was.
