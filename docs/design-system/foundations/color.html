Color

Colour says where you are, what is happening and what needs you. Every colour is a semantic role with a light and a dark value; components never read a raw hue.

Overview

Hewn's colour is two tiers. Primitives (--palette-*) are the 45 raw values in six ramps: slate (the dark theme), stone (the light theme), and blue, green, amber and red for accent and status. Semantic roles (--color-*, 76 tokens) give each value a job: a page background, a secondary text colour, the edge of an input. Components and pages read roles only; themes swap the primitive behind each role.

  • Dark is the prototype's palette. The Magic Patterns frames were drawn dark; every dark value comes from them.
  • Light is derived from the same roles on a warm stone canvas with slate ink, then tuned until every pair below passes WCAG 2.2 AA.
  • Blue is the only accent. It means interactive or live: the primary button, the selected tab, Running, the current stage, the focus ring.
  • Status is never colour alone. Green, amber and red always travel with an icon and a word (Succeeded, Paused, Failed).

Press t to switch theme: every value and ratio on this page is read live from tokens.css.

Palette ramps

Primitives are named by ramp and lightness step (50 lightest, 950 darkest). Steps are sparse on purpose: a step exists only because a role needs it. Do not use these in component or page CSS.

Status colours

Four statuses, five roles each: -bg (callout and strip fill), -fg (text on that fill and status words on surfaces), -border (decorative edge), -icon (the icon, ≥ 3:1) and -solid (fills that carry meaning: pipeline segments, dots, meters). Danger adds -solid-hover for the danger button and -strong for Failed and field errors on neutral surfaces.

Adding a brand theme

A brand theme (a white-label Hewn, a customer's accent) is one more [data-theme] block that overrides semantic colour roles. It never edits a component and never renames a token.

/* 1. tokens.py: add the brand's primitives to PALETTE (they become --palette-teal-*) */
/* 2. tokens.py: add a theme block that overrides SEMANTIC colour tokens only */
[data-theme="harbor"] {
  --color-accent: var(--palette-teal-600);
  --color-accent-hover: var(--palette-teal-700);
  --color-accent-active: var(--palette-teal-700);
  --color-accent-subtle: var(--palette-teal-50);
  --color-accent-subtle-hover: var(--palette-teal-100);
  --color-fg-accent: var(--palette-teal-700);
  --color-fg-link: var(--palette-teal-700);
  --color-focus-ring: var(--palette-teal-600);
  --color-brand-chip: var(--palette-teal-600);
  color-scheme: light;
}
/* 3. contrast-pairs.json is checked per theme: add "harbor" and run check_contrast.py */
  • Override the accent family as a set: --color-accent, -hover, -active, -subtle, -subtle-hover, --color-fg-accent, --color-fg-link, --color-fg-link-hover, --color-fg-on-accent, --color-focus-ring, --color-brand-chip.
  • Keep status hues. A brand that is itself green or red must still leave success green and danger red; pick a different accent step if they collide.
  • A dark variant is a second block ([data-theme="harbor-dark"]) with color-scheme: dark; copy the dark block and change the same roles.
  • Run check_contrast.py; aim for ≥ 4.8:1 on text and ≥ 3.3:1 on edges so small rendering differences cannot fail AA.
  • Do not touch --color-preview-*: the preview shows the customer's product, not the brand of the tool.

See Theming for how theme blocks, the OS preference and islands interact.

Usage

  • Read roles, never primitives: color: var(--color-fg-muted), not var(--palette-stone-700). A component that needs a new colour gets a new role (and a contrast pair), not a palette reference.
  • Text goes on the surface it was checked on. --color-fg-subtle passes on canvas, surface, raised, subtle and subtle-hover; it is not checked on the accent tint, so muted text on a selected row is --color-fg-muted.
  • One accent. Blue marks what is interactive or live; it is not decoration. Do not colour headings, icons or borders blue to add interest.
  • Status fills (-solid) are for marks that carry meaning (a pipeline segment, a meter, a dot). Status backgrounds (-bg) are for callouts and strips. Never put body text on a -solid fill.
  • Danger red is for failure and destruction. A destructive button appears only in a confirmation dialog; Failed and Blocked use --color-danger-strong text with the x-circle icon.
  • Disabled text (--color-fg-disabled) is exempt from contrast and is used only on genuinely disabled controls, never for de-emphasis.
  • Scrims (--color-bg-backdrop, --color-bg-scrim) carry alpha: they are the only translucent colours in the system.

Accessibility

  • 1.4.3 Contrast (minimum): every text pair above is ≥ 4.5:1 in both themes, including captions and placeholders; there is no large-text exemption in use.
  • 1.4.11 Non-text contrast: control edges, meaningful icons, fills and the focus ring are ≥ 3:1 against what is next to them. Decorative hairlines are exempt and documented as such.
  • 1.4.1 Use of colour: status is icon + word + colour; links in text are underlined; the invalid field has an icon and a message as well as a red ring.
  • More contrast (prefers-contrast: more): hairlines become --color-border-strong and subtle text becomes --color-fg-muted, in every theme.
  • Forced colours (forced-colors: active): the focus ring becomes Highlight and borders CanvasText, so edges survive Windows High Contrast.
