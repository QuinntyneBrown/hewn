Foundation

Layout

Five breakpoints, a 4/8/12-column grid whose gutters and margins step up with the screen, a 240px sidebar from 992px, and five page templates every screen is built from.

Overview

  • Mobile first: base styles target a 360px phone; every media query is min-width in rem, so it follows the reader's font size.
  • The grid, gutter and margin are tokens that change at md and lg; components read them instead of writing their own queries.
  • Navigation is a fixed sidebar from lg (992px) and a drawer behind a menu button below it (L2-046).
  • Every screen is one of five templates: the app shell, sign-in, settings, project detail and the error page.

Breakpoints

Hewn's breakpoints are the product's own, not the extraction skill's defaults (640/768/1024/1280). They come from requirement L2-046, which fixes the bands at XS below 576px, S from 576px, M from 768px, L from 992px and XL from 1200px; the mocks and the Angular BreakpointService are tested against those widths. 2xl (1536px) is added only to say where the content stops growing.

TokenValuepxL2-046 bandWhat changes
--layout-breakpoint-sm576pxSdialogs centre, page header goes horizontal, two-column forms.
--layout-breakpoint-md768pxM8 columns, tables show md columns, traceability 2-up.
--layout-breakpoint-lg992pxLsidebar appears, top bar hides, 12 columns, row lists become tables.
--layout-breakpoint-xl1200pxXLwide rails, traceability 4-up, project header goes horizontal.
--layout-breakpoint-2xl1536px–content stops growing at the container max.

Custom properties cannot be used inside @media, so queries repeat the value: @media (min-width: 62rem) means --layout-breakpoint-lg. The mocks had two extra breakpoints (40rem for dialogs and toasts, and max-width: 61.99rem queries); dialogs and toasts now switch at sm and every query is min-width.

Container and measure

.container caps content at --layout-container-max (1440px) and centres it; past 2xl the page grows margins, not content. Prose stops at --layout-measure; single-column forms at --layout-form-max (672px), which is why New direction has a rail beside its form instead of wider fields.

Usage

  • Start from a template; do not invent a page layout. A new screen is the shell plus a page header plus one of the content patterns (grid, row list, split).
  • Use .grid (reads --layout-columns) for column layouts and .grid--cards (auto-fill, minmax(18rem, 1fr)) for card collections; neither needs a media query.
  • Content inside the shell pads with .pad (--layout-margin); full-bleed parts (tabs, the project header, tables on phones) go edge to edge and pad their own content.
  • Write media queries as min-width in rem at the five values above, and nowhere else. If a component needs a different breakpoint, it needs a container-size rule, not a new viewport breakpoint.
  • Use 100dvh, not 100vh, for full-height layouts (shell, sign-in, error page).

Accessibility

  • 1.4.10 Reflow: every template works at 320px with no horizontal page scroll (L2-046 AC4 extends that to 2560px). Only tables and the log scroll horizontally, inside their own wrapper.
  • 2.4.11 Focus not obscured: the sticky top bar is 56px, and scroll-padding-top equals --layout-topbar-height, so a focused field is never hidden under it.
  • 2.4.1 Bypass blocks: every template starts with a skip link to #main; landmarks are nav (sidebar), header (top bar), main.
  • 1.3.2 Meaningful sequence: DOM order is visual order at every breakpoint; rails that move use grid placement, never order that would scramble focus.
  • 1.3.4 Orientation: no template locks orientation; landscape phones get the base layout.
