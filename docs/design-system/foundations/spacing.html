Spacing

One 4px scale for every gap, padding and margin, with three half steps for dense parts. Small numbers live inside components; large numbers separate them.

WCAG 2.2 AA
  • Overview
  • Scale
  • Inside and between
  • Control heights
  • Usage
  • Tokens

Overview

  • Token names count quarters of a rem: --space-4 is 1rem (16px), --space-1-5 is 0.375rem (6px). The name says the multiple of 4px.
  • Three half steps (0-5, 1-5, 2-5 = 2, 6, 10px) exist for dense parts the prototype draws tightly: nav link gaps, status icon offsets, stage rows. They replaced off-grid nudges in the mocks (0.15rem icon offsets, 3px strip gaps, a 3.1rem stage indent, a 0.6rem bar margin).
  • Spacing never scales with the viewport. A breakpoint changes which token a layout uses (the gutter goes from --space-4 to --space-6 to --space-8), never the token's value.

Rule of thumb: a component pads itself with ≤ --space-6; layout separates components with ≥ --space-6. If two things need more space between them than inside them, they are probably two groups and need a heading.

Control heights

Interactive parts take one of four heights; padding grows with height so labels stay optically centred. Below lg the small and medium heights are 44px, the same as --target-comfortable, so every control is a touch target (L2-046 AC4; see Accessibility).

Usage

  • Use a token for every gap, padding and margin. calc() with tokens is fine (calc(-1 * var(--space-4)) to bleed a card header); a raw 0.6rem is not.
  • Prefer gap on flex and grid parents (.stack, .cluster, .grid) to margins on children.
  • Half steps are for dense parts only. If you reach for --space-2-5 in a layout, use --space-2 or --space-3.
  • --space-20 and --space-24 are reserved; no current screen needs them. Large empty areas are a sign the layout is wrong, not that it needs more space.
  • Page margins and grid gutters come from --layout-margin and --layout-gutter, which pick a space token per breakpoint; do not hard-code them.
