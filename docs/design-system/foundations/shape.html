Foundation

Shape

Six radii that grow with the size of the thing, and two border widths. Edges are drawn as inset rings so borders never change an element's size.

WCAG 2.2 AA
  • Overview
  • Radius
  • Border widths
  • Usage
  • Tokens

Overview

  • Radius grows with size: 2px for bars and segments, 4px for small parts, 6px for controls and containers, 8px for overlays, 12px for bottom sheets, full for pills and dots.
  • The mocks had a 6px --radius-lg equal to --radius-md and off-grid 1px and 3px radii; the scale is now 2 / 4 / 6 / 8 / 12px on the 2px grid, and overlays (dialog, drawer, toast) take lg.
  • Edges are box-shadow: inset 0 0 0 var(--border-width-hairline) …, not border, so a state change (hover ring, invalid ring) never shifts the layout by a pixel.

Usage

ElementRadiusWhy
Pipeline segments, spend bars, skeleton chips--radius-xsLong thin marks; more radius makes them read as pills.
Segmented options, tile links, state links, inline code--radius-smSmall targets inside a larger control.
Buttons, inputs, selects, callouts, cards, tiles--radius-mdThe default for anything you click or that contains content.
Dialogs, drawers, toasts, menus' outer panel--radius-lgOverlays are larger and float; slightly rounder separates them.
Bottom sheets below sm--radius-xl (top corners)The sheet meets the screen edge; only the top corners round.
Avatars, pills, dots, meters, the theme toggle--radius-fullShapes defined by being round.
  • Nested shapes reduce radius: a 6px card holding 4px chips, not 6px inside 6px.
  • Never mix border and inset ring on one element; pick the ring.
  • Thick (2px) borders are state, not decoration: if nothing is selected, current or invalid, use the hairline.
