Form layout

Form layout arranges fields into a column, groups them, places the actions and reports problems in an error summary.

WCAG 2.2 AAStatus: stable<form novalidate>

Overview

Hewn's forms are short and serious: a direction runs to merged code without asking anything else, and settings change what every direction starts with. So every form is one column read top to bottom, fields are grouped by meaning, there is one primary action, and every problem is listed in one place before anything is submitted. See the forms pattern for validation timing and confirmation rules.

  • Single column (.form-col, max --layout-form-max): page forms such as New direction.
  • Two-up row (.form-grid.form-grid--2): only for short, related, optional fields (Stack + Existing repository), from sm.
  • With side rail (.split.split--form): the form beside a .rail that explains what happens next, from lg.
  • Settings section (.settings-section): heading and intro on the left, fields on the right from lg; each section saves on its own.
  • Dialog form: fields in .dialog__body, actions in .dialog__footer.
  • Actions bar (.form-actions): a hairline and generous space above; --inline drops the hairline for short forms.
  • Error summary (.callout.callout--danger.form-summary): a count, then one link per problem to its field.

Anatomy

  1. Error summaryDanger callout, role="alert", tabindex="-1"; title counts the problems; links jump to fields.
  2. FieldsOne column, --space-6 apart.
  3. Two-up row.form-grid--2: two columns from sm, --space-6 gap.
  4. Optional fieldOptional fields go after required ones.
  5. Actions bar.form-actions: --space-10 above, hairline, primary first then Cancel; --space-3 gap.

Sizes

Forms have widths rather than sizes:

  • Page form column: --layout-form-max (42rem), left-aligned in the content area.
  • Rail beside it from lg: 20rem, then --layout-rail-aside from xl.
  • Dialog form: --layout-dialog-width (28rem); --layout-dialog-width-lg when the body shows code.
  • Settings: a 16rem intro column and the rest for fields from lg.
  • Short numeric fields keep fixed widths (money 10rem, units 6rem) inside any of these.

Responsive behaviour

  • Below sm (36rem): one column; .form-grid--2 stacks; the actions bar wraps, primary first; dialogs become bottom sheets with a sticky footer.
  • From sm: .form-grid--2 pairs fields; dialog footers sit in a row, right-aligned.
  • From lg (62rem): .split--form puts the 20rem rail beside the form with a hairline; settings sections become a 16rem intro column plus fields.
  • From xl (75rem): the rail widens to --layout-rail-aside. The form column never exceeds 42rem, so line length stays readable on wide screens.

Theming

Layout uses spacing and border tokens only (--space-*, --border-width-hairline, --color-border-default for the actions bar and rail rules). The summary is a danger callout and themes with it. Field colours come from the field component tokens.

Accessibility

Role and pattern

<form novalidate> with custom messages, following the W3C tutorial on user notifications and grouping controls. Settings sections are <form aria-labelledby> (or <section> when they hold no form) so each is a named region.

Keyboard

KeyAction
TabFollows visual order: summary links, fields top to bottom, then actions.
Enter in a single-line fieldSubmits the form.
Enter on a summary linkMoves focus to the field (script calls focus() on the target, not just the scroll).
Esc in a dialog formCloses without saving; if fields have changed, asks first.

Focus

On submit with errors, focus moves to the summary (tabindex="-1"). On a server error, focus moves to the danger callout. While submitting, focus stays on the busy button. On success in place (Settings) focus stays and the success callout is announced; on success that navigates, focus goes to the new page's heading.

Labelling

The summary title counts the problems (3 things to fix before Hewn can start) and each link repeats the field's error in short. Groups use <fieldset> + <legend>. Form-level callouts use role="alert" for failures and role="status" for rate limits, success and read-only notes.

Motion

No layout animation: the summary and callouts appear in place and the page scrolls to them instantly (smooth scrolling is off under reduced motion).

Touch

Actions are 40px buttons with 12px between them; on phones in dialogs they are full width. Summary links are text links in a list, each on its own line.

Content

  • Summary title: a count and the goal: 3 things to fix before Hewn can start, 2 things to fix.
  • Summary items: the field's problem, short, in the same order as the fields; never different words from the field error.
  • Primary action names the outcome: Start direction, Save defaults, Raise and resume.
  • Server failures say what happened, what was kept and what to do: Nothing was created; your text is kept below. Try again.
  • Success says what changed and what did not: Directions already running keep theirs.
