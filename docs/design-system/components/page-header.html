Page header

The top of every top-level page: the page's one <h1>, a line that says what the page holds or how it stands, and the page's own actions or filters.

Overview

Dashboard, Projects, Workers, Audit and Settings open with a page header. Project pages use the richer Project header instead (breadcrumb, status, spend, controls, section tabs); sign-in and the error pages have their own layouts.

  • Title: the page's <h1>, the same word as the sidebar item (Workers).
  • Description: one line of live summary or purpose: 7 projects · sorted by last activity, 2 directions running · 2 need attention · $86.40 spent today, One container image, local or cloud. At most one worker leases a project at a time.
  • Actions: at most one primary, small (New product, New worker token), or the page's filters (Audit's project and action selects), or a desktop-only tool (Edit layout).

Examples on this page use an <h2> styled as the title, because the documentation page owns its own <h1>. In the product it is always <h1>.

Anatomy

  1. TitleThe <h1> in --text-h1 with tight letter spacing.
  2. Description.page-header__desc: --text-body-sm, muted, --space-1 under the title; wraps.
  3. ActionsA .cluster of small buttons or labelled filters, aligned to the title's baseline row from sm.
  4. Container.page-header: column below sm, row from sm; --space-6 / --space-4 padding, --space-8 from lg.

Sizes

The page header has one size; only its padding grows at lg.

States

The header has no interactive states of its own; its buttons and selects carry theirs. It does change with the page's state:

Page stateHeaderExample
DefaultTitle, live description, actions.pages/workers/default
LoadingTitle and actions render immediately; the description is a skeleton line until the summary arrives, so the <h1> is never missing.pages/projects/loading
Empty / errorUnchanged; the empty or error state sits below it. The primary action stays, because it is usually the way out (New worker token on an empty Workers page).pages/workers/empty
ForbiddenTitle kept; the description says why (Only Owners can read the audit log.); actions and filters removed.pages/audit/forbidden
ViewerOwner-only actions are not rendered.pages/workers/viewer

Responsive behaviour

  • Below --layout-breakpoint-sm (576px): one column. Title, description, then the actions under them, left aligned; padding --space-6 top and bottom, --space-4 sides (the page margin). The description wraps.
  • From sm (576px) to lg: a row; the title block takes the space and the actions sit at the end, aligned to the bottom of the block.
  • From lg (992px): padding --space-8 top and sides, --space-6 bottom, matching --layout-margin; desktop-only actions (.lg-only) appear.
  • xl (1200px): unchanged; the header spans the main column.

Theming

The header has no background or border of its own; it sits on the canvas and inherits --color-fg-default for the title and --color-fg-muted for the description. In dark both lighten with the canvas. If a page needs a banded header, put it on --color-bg-surface with a hairline --color-border-default bottom edge, as the project header does.

Accessibility

Role and pattern

No widget: a heading and its context. The <h1> is the first heading inside <main> and matches the document <title> and the current sidebar item (WCAG 2.4.2, 2.4.6; see APG headings). Filters in the header are native <select>s, each with a label.

Keyboard

KeyAction
TabMoves from the skip-link target through the header's actions, then into the page.
H (screen reader)The title is the first heading on the page.

Focus

After a route change focus moves to the <h1> (with tabindex="-1", no visible ring for programmatic focus), so the new page is announced by name.

Labelling

The title names the page. Filters have visually hidden labels (Project, Action) because the selected option reads as the visible label. A live description ($86.40 spent today) is not a live region; the dashboard's tiles announce changes.

Motion

No motion.

Touch

Small buttons in the header are 32px tall, alone in their cluster or 8px apart, above the 24px minimum; below lg they sit on their own line, away from the title.

Content

  • Title: the sidebar's word for the page, one or two words, no punctuation.
  • Description: one sentence or a dot-separated summary (7 projects · sorted by last activity); numbers are tabular and current.
  • Primary action: verb + object, matching the dialog or page it opens (New worker token).
  • Do not repeat the title in the description (Workers: your workers).
