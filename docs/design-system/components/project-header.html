Project header

The project header sits on every project screen: which project this is, where its code lives, how it is doing, what it has spent, and the tabs between its views.

Overview

Every screen under a project (Pipeline, Backlog, Designs, Design system, Decisions, Artifacts, Traceability) starts with this header. It replaces the generic Page header there. It combines a Breadcrumb, the project name as the page's h1 with its status, the repository, a spend meter (Progress bar), percent complete, the direction controls for Owners, and navigation Tabs.

The controls change with the status, so the header is where an Owner pauses, resumes, retries or cancels the direction from any project view.

Anatomy

  1. BreadcrumbBack to Projects; the current crumb is aria-current="page".
  2. NameThe page h1 in --text-h1.
  3. StatusIcon + word, the same status badge as everywhere else.
  4. Meta lineDirection kind and start date, the repository link, and for Owners the skills update link.
  5. Spend meterrole="meter", money as text above it; turns warning at 80%.
  6. ControlsOwner only: Pause or Resume or Retry stage, plus Cancel.
  7. TabsNavigation links to the project's views; the current one has aria-current="page".

Variants

The status decides the controls; the role decides whether there are any.

Responsive behaviour

  • Base (360px): padding 20px top, 16px sides; name and status wrap as a cluster; the meta line wraps; the stats (spend, complete, controls) stack under the title block; tabs scroll horizontally inside .phead__tabs with the scrollbar hidden and a 44px touch height.
  • From lg (62rem): padding grows to 24px top and 32px sides to line up with the page content; tabs drop to 40px (--control-height-md).
  • From xl (75rem): the title block and the stats sit on one row (.phead__row becomes a row), stats aligned to the bottom right.
  • The name truncates with an ellipsis rather than wrapping under the status; the spend block keeps a minimum width of 11rem so money never wraps.

Theming

The header is a --color-bg-surface band with a hairline --color-border-default bottom edge, so it reads as part of the chrome in both themes. The meter follows the progress bar's tokens; tabs follow the tab tokens. No header-specific colour tokens exist; override the tab and meter component tokens instead.

Accessibility

Role and pattern

A <header> inside <main> (not the banner landmark) holding a breadcrumb nav, the page h1, a meter, buttons, and a second nav labelled Project sections. The tabs navigate to other pages, so they are links with aria-current="page", not the ARIA tabs pattern.

Keyboard

KeyAction
TabBreadcrumb link, repository link, skills link, controls, then each section link in order.
EnterFollows a link; on a control button it acts (Pause, Resume, Retry stage, Cancel opens its dialog).
SpaceActivates the focused button.

Focus

Every link and button shows the shared focus ring. The tab strip scrolls the focused tab into view on phones. After Pause or Resume the button swaps label in place and keeps focus.

Labelling

The project name is the page's only h1. The two navs have distinct labels (Breadcrumb, Project sections). The meter carries aria-valuetext="$184.20 of $400.00", so it is read as money rather than 184.2. The status is icon plus word.

Motion

Only the tab underline transitions (--duration-base) and the Running status icon spins (--duration-spin); both stop under reduced motion.

Touch

Tabs are 44px tall below lg; control buttons are small (32px) with 8px between them; the repository link has an inline target in a line of text (exempt under 2.5.8).

Content

  • Kind and date: Product direction · started 7 Nov or Feature direction · started 8 Nov; finished 8 Nov once Complete.
  • Repository as owner/repo in mono, linking to GitHub.
  • Money is always amount and budget: $184.20 of $400.00, two decimals, tabular.
  • Tabs are nouns in sentence case: Pipeline, Backlog, Designs, Design system, Decisions, Artifacts, Traceability.
  • Controls are verbs: Pause, Resume, Retry stage, Cancel.
