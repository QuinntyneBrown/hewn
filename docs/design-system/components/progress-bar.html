Progress bar

Progress bars show how far something has got (a project, an upload) and meters show how much of a limit is used (spend against budget). Both are the same thin bar.

WCAG 2.2 AAStatus: stablerole="progressbar" / role="meter"

Overview

One component, two roles, chosen by what the number means:

  • Progress (role="progressbar"): completion of a task that ends: a project’s percent complete, an import, a capture. Goes green (.meter--ok) at 100%.
  • Meter (role="meter"): a quantity within a known range that is not a task: spend against budget, worker capacity. Turns warning at 80% because the direction pauses itself at 100%.
  • Indeterminate (.meter--indeterminate): a task whose length is unknown and that takes long enough to need more than a Spinner.

Use the Pipeline strip for stage-by-stage progress and a Stat when the number itself is the point.

Anatomy

  1. Label.progress__label: what is measured, left.
  2. ValueRight, tabular: amount of limit, or percent.
  3. Fill.meter__bar, width from --value.
  4. Track.meter: 4px, fully rounded, --color-border-default.

Inline (.meter--inline) fixes the width at 3.5rem for table and row cells; otherwise the bar takes the width of its container.

States

Not interactive: no hover, focus or disabled states. Its states are its values and its thresholds.

———
  • Warning (.meter--warn) applies to meters from 80% of the limit; the value text says it: $200.00 of $250.00.
  • Danger (.meter--danger) is for a failed task frozen at the point it failed (an import that stopped at 40%), alongside an error message.
  • Updating: the fill width changes without animation; announce milestones (not every percent) through the surrounding live region.

Responsive behaviour

  • The bar is fluid at every breakpoint; label and value sit on one line above it and wrap only if the label is long.
  • In row lists the inline bar and its percent show from lg; below lg the percent stays and the bar hides with its column.
  • In the project header the spend block keeps a minimum width of 11rem so money never wraps.

Theming

The fill reads --meter-fill, which each modifier sets (--color-accent, --color-fg-muted, --color-success-solid, --color-warning-solid, --color-danger-icon). Every fill keeps 3:1 against the track in both themes.

/* Worker capacity uses the info fill */
.capacity .meter { --meter-fill: var(--color-info-solid); }

Accessibility

Role and pattern

role="progressbar" for completion and APG meter (role="meter") for a value in a range, each with aria-label, aria-valuemin, aria-valuemax and aria-valuenow; add aria-valuetext whenever the number is not a plain percent ($184.20 of $400.00). Indeterminate progress omits aria-valuenow; the region that is loading also gets aria-busy="true". See the WAI-ARIA progressbar role.

Keyboard

KeyAction
NoneNot focusable. The value is read in reading order or from the row it belongs to.

Never takes focus.

Labelling

Name it after what it measures: Spend, Ledgerline complete, Importing the CSV statement. The visible value text and aria-valuetext say the same thing.

Motion

The indeterminate sweep runs on --duration-pulse; under reduced motion it stops as a still 40% segment, and the label still says the task is under way. Determinate fills change width instantly.

Touch

Not a target.

Content

  • Label what is measured, value on the right: Spend · $184.20 of $400.00.
  • Money with two decimals; percent with no decimals: 62%.
  • At a threshold, the value text says what happens: It pauses at $250.00.
  • Indeterminate labels use the progressive verb: Importing the CSV statement.
