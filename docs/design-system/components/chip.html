Chip

Chips are compact, rounded controls for filtering a list by a few values, showing which filters are on, or tagging an item. They are the planned replacement for the stage and action selects on Decisions and Audit.

WCAG 2.2 AAStatus: core set; not yet in the mocksNative <button aria-pressed>

Overview

Use filter chips when a list has a handful of filter values (up to about seven) that people switch between often, such as the six stages on Decisions; a Select stays the right choice for longer lists, such as the eleven actions on Audit. Use removable chips to show the filters that are on, each with its own remove button. Use static chips as read-only tags (a requirement ID, a skill). For status use a status; for mutually exclusive view switches use a segmented control.

  • Filter: a toggle button with aria-pressed; pressed chips show a check and the accent tint.
  • Removable: a static chip with a .chip__remove button labelled with what it removes.
  • Static (.chip--static): a tag, not interactive.

Anatomy

  1. Check (pressed)A ✓ in --color-fg-accent, drawn by CSS, only when pressed.
  2. LabelCaption type, medium weight.
  3. Container32px tall (--control-height-sm), --radius-full, 1px --color-border-strong ring.
  4. Remove button24px (--target-min) round button with an x icon and an aria-label.

Responsive behaviour

  • Chips wrap onto new lines in a .cluster; they never scroll sideways or truncate.
  • On phones (below sm) a group of more than four filter chips can scroll horizontally in one row inside its own container, like tabs; keep the pressed chip in view.
  • Sizes do not change with the breakpoint; use medium on phones so targets stay 32px.

Theming

Chips read --color-bg-surface, --color-fg-muted and --color-border-strong; hover --color-bg-subtle-hover; pressed --color-accent-subtle with an --color-accent ring and --color-fg-default text. In dark the pressed tint is the deep blue selection colour and the ring the lighter dark accent.

Accessibility

Role and pattern

Filter chips are toggle buttons (<button aria-pressed>) inside a role="group" with an aria-label, following the APG button pattern. When exactly one must be on, use a radio group instead. Removable chips are text plus a labelled button. Static chips are plain text.

Keyboard

KeyAction
Tab / Shift + TabMoves chip to chip (each is a tab stop), and to each remove button.
Enter, SpaceToggles a filter chip, or removes a removable chip.
EscNo effect.

Focus

The shared ring (2px, 2px offset) around the whole rounded chip, or around the remove button. After removing, focus goes to the next chip or the group's first control; it never drops to the page.

Labelling

The label is the value (Stack). The group's label says what is filtered (Filter decisions by stage). Remove buttons say what goes: Remove filter Project: Ledgerline. When filtering changes the results, announce the new count in a polite status (2 decisions in Stack).

Motion

Background changes over --duration-fast; instant under reduced motion.

Touch

Medium chips are 32px tall and small chips 24px, with the cluster's 8px gap between them. The remove button is 24px and sits inside the chip's end padding.

Content

  • Labels are the values themselves, in sentence case, one to three words: Design system, Increments.
  • Removable chips name the filter and value: Project: Ledgerline.
  • The first filter chip is the unfiltered option when it helps (All stages).
  • No counts inside chips unless every chip has one.
