Button group

Button groups put a few related options in one control: a segmented choice of view, a pair of sibling pages, or a toolbar of tools.

WCAG 2.2 AAStatus: stablerole="group" / role="toolbar"

Overview

A segmented control switches between two to five mutually exclusive views of the same thing, in place: the width and theme of a design preview. The mocks also use it to switch between the two New direction forms, which are separate pages. Each job uses a different element:

  • Chooses a view in place: <button aria-pressed> options in a role="group" with a label. Pressing one sets it to true and the others to false.
  • Goes to a sibling page: <a href> options with aria-current="page" on the current one (New product / Feature for a product).
  • Sets a form value that is submitted: not a segmented control; use a radio group (real radios, arrow keys) instead.
  • Toolbar (.toolbar, role="toolbar"): a row of independent tools for one surface, with one tab stop and arrow keys between tools.

Never give links role="radio": the mocks did, so arrow keys did nothing and activating an option navigated away from a control that claimed to be a radio group. With more than five options or long labels, use Tabs for views or a Select for values.

Anatomy

  1. Container.segmented: --color-bg-surface, 1px inset --color-border-strong, --radius-md, padding --space-0-5 (--space-1 large).
  2. Option.segmented__opt: 32px (40px large), --radius-sm, --text-caption medium in --color-fg-muted.
  3. Selected optionRaised: --color-bg-surface-raised, its own --color-border-strong ring, --color-fg-default, medium weight.
  4. Group labelaria-label on the group (Preview width); not visible, so the context must make the meaning obvious.

Both themes

New productFeature for a product
New productFeature for a product
  • Selected is shown by a raised fill, a ring and a heavier weight together, so it does not depend on colour.
  • Active has no separate style; the option becomes selected on release.
  • Disabled options keep their place at 50% opacity, so the set does not reflow; say why in a tooltip or nearby text.

Responsive behaviour

  • Options never wrap or truncate. At 360px the five width options (about 10rem) and the large direction-type pair (about 19rem) fit inside the 16px margins.
  • Below sm, a group that would not fit becomes a select with the same label; the designs preview hides its width group below md, where the preview is already the phone width.
  • Medium options are 32px tall at every breakpoint (above the 24px minimum, with no gap between options inside one control); large options are 40px.
  • Toolbars sit in the header of the surface they act on and wrap to their own line below sm.

Theming

No component tokens yet: the group reads --color-bg-surface, --color-border-strong, --color-bg-subtle (hover), --color-bg-surface-raised (selected) and --color-fg-muted / --color-fg-default. In dark, the selected option is the lighter raised surface on the darker group, so selection still reads as lifted.

Accessibility

Role and pattern

Choosing groups are toggle buttons (APG button pattern, aria-pressed) in a labelled role="group"; navigating groups are links with aria-current. Toolbars follow the APG toolbar pattern. If a choice must behave as one radio group (arrow keys move the selection), use real radios.

Keyboard

KeyAction
Tab / Shift + TabSegmented: moves to each option in turn. Toolbar: moves into the toolbar (to the last-focused tool) and out.
Space / EnterPresses the focused option (buttons) or follows it (links, Enter only).
← →Toolbar only: moves focus to the previous / next tool.
Home / EndToolbar only: first / last tool.

Focus

The shared 2px ring with 2px offset on the focused option; it is drawn outside the group's edge so it is visible against both the group and the page. Pressing an option keeps focus on it.

Labelling

The group has an aria-label naming the setting (Preview width); each option has a visible label or an aria-label (Light, Dark). A title (992 px) adds a tooltip but is not the name. Announced as Preview width, group, L, toggle button, pressed.

Motion

Background and colour change over --duration-fast; the selected fill does not slide between options. Reduced motion zeroes the transition.

Touch

Options are at least 32px tall and as wide as their label plus --space-2 each side (never under 32px). The whole option is the target; no hover-only information except the width tooltip, which repeats nothing essential.

Content

  • Option labels are one or two words, parallel and in sentence case: New product / Feature for a product.
  • Abbreviations are fine when the set makes them obvious (XS–XL); put the full value in the tooltip.
  • Icon-only options need an unambiguous icon and an aria-label; use them only for well-known pairs such as light and dark.
  • The group label names the setting, not the action: Preview width, not Change width.
