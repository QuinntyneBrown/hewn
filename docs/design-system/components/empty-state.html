Empty state

Empty states fill the space where a list or view would be when there is nothing to show yet, nothing matches, the person may not see it, or it failed to load.

WCAG 2.2 AAStatus: stable

Overview

Every list, table, tile and project view has an empty state. It replaces the content in place, keeps the page chrome, and always explains why it is empty and what happens next. One action at most, and only one the person can take.

KindIconFormulaAction
First runThe object's icon, subtleWhat will be here and how it gets here.The one action that fills it, Owners only.
Not yet (pipeline)The object's icon, subtleWhich stage produces it and that it has not run yet.Open the pipeline.
No resultssearchThat nothing matches, and why if known.Clear filters / Show all.
Forbiddenlock, warningWho can see it and why; reveal nothing else.A way back.
Erroralert-triangle, dangerWhat failed, the code, and what still works.Try again plus a way back.

A whole page that cannot be shown (unknown project, server error) is an Error page; a failure next to content that did load is an alert.

Anatomy

  1. Icon28px (--size-icon-xl), --color-fg-subtle; danger for errors, warning for forbidden.
  2. Title.empty__title: a heading at the level the content would have had (h2 on a page, h3 or a p in a tile).
  3. Text.empty__text: why it is empty and what happens next; at most 28rem wide.
  4. Action (optional)One button or link; error states may add a way back.

States

The empty state is not interactive; its action has the button states. Pointer and focus states are forced with data-state.

VariantDefaultHoverFocusBusy
Action
  • Retry in an error state turns busy (Trying again…) and either loads the content or re-renders the error with the new code.
  • Error states use role="alert" when they replace content after a failed request; first-run, no-results and forbidden states have no role and are read in order.

Responsive behaviour

  • Base (360px): start-aligned in the content column, icon above text, action below; text wraps at 28rem or the column, whichever is narrower.
  • Tile variant (.empty--center) centres everything at every width.
  • Error states with two actions wrap the buttons onto two lines below sm.
  • Padding stays the same at every breakpoint so a page's empty state sits where its first row would.

Theming

Title --color-fg-default, text --color-fg-muted, icon --color-fg-subtle (danger icon for errors, warning icon for forbidden); a hairline --color-border-default top edge separates it from the page header. Nothing else changes between themes.

Accessibility

Role and pattern

No widget role. The title is a real heading at the level the missing content would have had, so heading navigation still finds the section. Error states that replace content after a failed request use role="alert" (APG alert). Icons are aria-hidden.

Keyboard

KeyAction
TabReaches the action (and the way back in error states).

Focus

After Clear filters, focus moves to the first result or the results heading; after a successful retry, to the content's heading.

Labelling

The title says what is missing (No projects yet), so it works as a heading out of context. Buttons name the action, not Click here.

Motion

None. The empty state replaces the skeleton without a transition.

Touch

Actions are medium buttons (40px); small (32px) inside tiles.

Content

  • Title: what is missing, plainly: No projects yet, No entries match these filters, You don’t have access, Projects couldn’t load.
  • Text: why, and what happens next. For pipeline outputs name the stage: The backlog is produced by stage 9, Estimates.
  • Errors give the code and reassure: The Hewn API returned 503 Service Unavailable. Your directions are still running on their workers.
  • Forbidden reveals nothing beyond who can see it: only Owners can read it.
  • If nothing needs doing, say so: Nothing to do here.
