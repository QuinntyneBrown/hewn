Dialog

A modal dialog asks for one decision or a few fields without leaving the page: stop every worker, delete a project, raise a budget, create a worker token. Centred from sm; a bottom sheet on phones.

WCAG 2.2 AAStatus: stableAPG Dialog (Modal)role="alertdialog" for destructive

Overview

Use a dialog when the person must decide before the page can continue, and the decision is small: a destructive confirmation, a short form (one to three fields), or a result that must be read once. Use a page when the task has more than three fields or needs its own URL (a new direction), a Drawer for navigation, a Menu for a list of actions, and a Toast to report an outcome.

  • Confirmation (role="alertdialog"): states the consequence and offers the safe action and one danger action (Stop all workers?, Revoke build-box-02?).
  • Destructive with typed confirmation: for irreversible deletes the person types the object’s name before the danger button enables (Delete Harbor CRM?).
  • Form (role="dialog"): a few fields and a primary action (Raise Kiln Booking’s budget, Add a GitHub login).
  • Large (.dialog__panel--lg): a list to review or a result to copy (Update Ledgerline’s skills?, New worker token).
  • With icon and close (.dialog__head, .dialog__icon, .dialog__close): optional; the mocks rely on Cancel and Escape instead of a close button.

Anatomy

  1. Icon (optional).dialog__icon: 40px danger disc for destructive confirmations, aria-hidden.
  2. Title.dialog__title (h2, --text-h2); the dialog’s name via aria-labelledby.
  3. Description.dialog__text: the consequence, --text-body-sm muted; linked with aria-describedby.
  4. Footer.dialog__footer: safe action then confirm. A row, end-aligned, from sm; stacked with the confirm on top and sticky below sm.
  5. Panel.dialog__panel: --color-bg-surface-raised, --shadow-4, 24px padding, --radius-lg (--radius-xl top corners as a sheet).

Variants

Every example sits on a sample of --color-bg-backdrop; in the product the backdrop covers the viewport and the page behind is inert.

  • Default: focus moves to the first field, or to the safe action (Cancel) in a confirmation. In the typed confirmation, Delete project stays disabled until the name matches.
  • Invalid: the field gets aria-invalid="true" and an error linked with aria-describedby; focus returns to the field.
  • Busy: the confirm button is aria-busy + aria-disabled with a progressive label, fields are readonly, and Escape and Cancel still work only if the request can be abandoned safely.
  • Failed: a danger callout with role="alert" appears above the body, says what happened and what is safe; the confirm button becomes Try again. The dialog never closes on failure.
  • Success: the dialog closes and a toast reports the outcome; when the result must be read (a new worker token), the dialog shows it with a single Done.

Responsive behaviour

  • Base (below --layout-breakpoint-sm, 576px): a bottom sheet. Full width, top corners --radius-xl, slides up, max 90dvh, safe-area padding at the bottom. The footer is sticky at the bottom of the sheet and stacks its buttons full width with the confirm on top.
  • From sm: centred with 16px around, --radius-lg, rises in; the footer is a row, end-aligned, confirm last.
  • Width never exceeds the size’s max (24 / 28 / 32rem); content does not get wider on large screens.
  • Long content scrolls inside the panel; the page behind never scrolls while the dialog is open.

Theming

Component tokens: --dialog-bg (--color-bg-surface-raised), --dialog-ring (--color-border-default), --dialog-shadow (--shadow-4), --dialog-pad (--space-6), --dialog-width. The backdrop is --color-bg-backdrop; layers are --z-overlay (backdrop) and --z-modal (dialog).

/* A roomier dialog for a review step */
.dialog--review { --dialog-pad: var(--space-8); --dialog-width: var(--layout-dialog-width-lg); }

In dark the raised surface is lighter than the page and the backdrop darker, so the dialog stays the brightest surface; the danger button keeps its red ring against the raised surface.

Accessibility

Role and pattern

APG Dialog (Modal): role="dialog" (or role="alertdialog" for destructive confirmations, see the Alert Dialog pattern), aria-modal="true", aria-labelledby the title and aria-describedby the description. The rest of the page is inert while it is open. A native <dialog> opened with showModal() is equivalent. Documentation examples omit aria-modal because they are not modal.

Keyboard

KeyAction
Tab / Shift + TabCycles through the dialog’s controls only; focus is trapped.
EscCloses the dialog (same as Cancel), unless a request in flight cannot be abandoned.
EnterIn a field, submits the form dialog; on a button, activates it.
SpaceActivates the focused button, toggles a radio.

Focus

On open, focus goes to the first field (form dialogs) or to the safe action (confirmations, so Enter never destroys). On close, focus returns to the control that opened it; if that control is gone (the deleted project’s row), to the page heading. A busy button keeps focus.

Labelling

The title is a question or a task that names the object (Delete Harbor CRM?); the description states the consequence and is read on open. Error text is linked to its field; the failed callout is announced with role="alert".

Motion

The sheet slides up (sheet-in) and the centred dialog rises in (rise-in), both --duration-slow on --ease-enter. Reduced motion zeroes the durations; the dialog simply appears.

Touch

Footer buttons are 40px tall and full width in the sheet; the close button is 40px. Nothing in a dialog relies on hover.

Content

  • Title: a question for confirmations (Stop all workers?), a task for forms (Raise Kiln Booking’s budget). Name the object; never Are you sure?
  • Description: what happens and what is kept, in one or two sentences (Ledgerline and Tidewater keep their last checkpoints…). Say This can’t be undone only when true.
  • Confirm button repeats the verb of the title (Stop all workers, Revoke token); the safe action says what it keeps when Cancel would be ambiguous (Keep running, Not now).
  • Failed callout: what did not happen, why, what is safe (Nothing was removed; try again.).
