Form field

The form field wraps one control with its label, hint, error, success message and counter, in a fixed order and spacing.

Overview

Every text field, Textarea and Select sits in a .field. It owns the parts that are the same for every control, so each form reads the same way: label on top, control, then one line of help that turns into an error when something is wrong. Radio and checkbox groups use the same parts on a <fieldset>, with the legend as the label.

  • Label (.field__label): always visible, above the control; (optional) in a lighter weight when the field can be left empty.
  • Hint (.field__hint): the rule, the default or the consequence, one line where possible.
  • Error (.field__error): replaces the hint; icon + text in --color-danger-strong.
  • Success (.field__success): rare; only for a check the server ran, such as repository access.
  • Counter (.field__counter): right-aligned, for limits the person can reach.
  • Static value: a <p class="field__label"> above a value that is not a control (the new token).

The field also owns validation timing: validate a field when it loses focus after the person has changed it; once a field shows an error, re-validate on every input so the error clears as soon as it is fixed; on submit, validate everything, show the error summary and move focus to it. Server-side checks (name already used, no repository access) appear after submit.

Anatomy

  1. Label<label class="field__label" for>; --text-label. Gap below: --space-2 (.field__control).
  2. ControlAny field control at full width.
  3. Error (or hint)--space-1-5 below the control; icon icon--sm + text, --text-body-sm, --color-danger-strong. Hints are --text-caption, --color-fg-subtle.
  4. Counter--space-1-5 below; right-aligned, tabular.

Sizes

The field has no sizes of its own; it follows its control's size and always fills its column.

  • Error replaces the hint because the error repeats the rule; when the hint holds something else the person still needs, keep both (error first).
  • Success only follows a server check and disappears when the value changes.
  • Read-only and disabled keep the hint visible so the reason stays readable.

Responsive behaviour

  • The field is always one column inside: label, control, message. It never puts the label beside the control in a form; side labels are only for filters (.inline-label).
  • Between fields: --space-6 in pages, --space-5 in dialogs; the same at every breakpoint.
  • From sm two fields can share a row in .form-grid--2; their messages wrap independently, so rows may differ in height.
  • Messages wrap freely; the error icon stays on the first line (margin-top: --space-0-5).

Theming

.field declares the field component tokens (--field-bg, --field-fg, --field-border, --field-ring, --field-invalid) that its control reads, so overriding them on one field or a whole form re-skins every control inside. Messages use semantic tokens directly: --color-fg-subtle, --color-danger-strong, --color-success-fg.

Accessibility

Role and pattern

No ARIA widget: native label association plus aria-describedby and aria-invalid, as in the W3C tutorials on instructions and user notifications.

Keyboard

KeyAction
TabMoves between the controls; labels, hints and errors are not focusable.
Click or tap the labelFocuses (or toggles) the control.

Focus

Focus rings belong to the controls. The field never steals focus while the person types; errors that appear on blur do not move focus back.

Labelling

<label for> names the control; aria-describedby lists the error (or hint) and the counter, in reading order. The error icon is aria-hidden; errors start with the field's name so they make sense when read alone. Fieldsets use <legend class="field__label">. Live errors that appear on blur are not announced as alerts; they are read when the person returns to the field and listed in the summary on submit.

Motion

Messages appear without animation, so nothing shifts while someone is reading.

Touch

The label extends the control's target. Messages are text, not targets.

Content

  • Label: a noun, sentence case, no colon; add (optional) rather than marking required fields.
  • Hint: the rule, the default or the consequence (Warns again at 80%. $250.00 spent so far.).
  • Error: what is wrong, then how to fix it, using the field's name and real numbers (New budget must be more than the $250.00 already spent.).
  • Success: what was verified (Hewn can write to northwind/ops-portal.), never Looks good!
