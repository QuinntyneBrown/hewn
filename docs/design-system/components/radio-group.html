Radio group

Radio groups choose exactly one of a few options and show them all, with what each one means.

WCAG 2.2 AAStatus: stableNative <input type="radio">

Overview

Use a radio group when exactly one of two to five options must be chosen and the person benefits from seeing every option and its consequence at once: a user's role, where a worker runs, the theme. With more options, or options that change, use a Select; for an independent on/off choice use a Checkbox or Switch; for switching a view in place (width, light/dark preview) use a button group.

  • Vertical with descriptions (.choices): the default, used for Role in Add a GitHub login and Theme in Settings.
  • Horizontal (.choices--row): two or three short options, used for Location in New worker token.
  • With icons: an icon--sm before the text reinforces the option; it is decorative.
  • Card (.choice--card): bordered options that tint when chosen, two-up from sm.

Always preselect the safest option (Viewer, System) unless the choice is consequential enough that a default would be presumptuous; then start empty and validate.

Anatomy

  1. Legend.fieldset > legend, --text-label; names the group.
  2. RadioNative radio, --size-icon-md, accent-color: --color-accent.
  3. Icon (optional)icon--sm, decorative, aria-hidden.
  4. Option label--text-body-sm in --color-fg-default.
  5. Description<small>, --text-caption, --color-fg-subtle.

Role
  • Disabled: individual options are disabled only when they cannot apply (Owner when the person is not an Owner); disabling a whole group while an unrelated form submits is wrong.
  • Hover is the browser's on plain radios; cards fill with --color-bg-subtle.
  • Checked cards tint with --color-accent-subtle and an accent edge, so the choice is shown by more than the dot.

Responsive behaviour

  • Vertical groups are the same at every breakpoint.
  • .choices--row wraps below sm when the options do not fit; it never squeezes descriptions onto one line.
  • Cards stack below sm and sit two-up in .form-grid--2 from sm (36rem).
  • In Settings (lg and up) the group sits in the right column of the .settings-section grid, beside its section heading.

Theming

The radio is native, coloured by accent-color: var(--color-accent); its unchecked edge follows color-scheme. Cards use --color-bg-surface and --color-border-default, switching to --color-accent-subtle and --color-accent when checked; in dark the tint is the deep blue that keeps text at 4.5:1.

Accessibility

Role and pattern

Native radios sharing a name, inside <fieldset> with <legend>. Keyboard behaviour is the browser's and matches the APG radio group pattern. Do not build radios from links or buttons with role="radio".

Keyboard

KeyAction
TabMoves into the group, to the checked radio (or the first when none is checked), then out of the group.
↓ / →Checks the next option (wraps).
↑ / ←Checks the previous option (wraps).
SpaceChecks the focused option when none is checked.

Focus

The shared ring around the radio. The group is a single tab stop. Moving with arrows changes the value, so changing a radio must never navigate or submit; theme changes apply but keep focus in place.

Labelling

The legend names the group and is read once on entry (Role, group). Each option's label and description form its name (Viewer, Watches every project, radio button, 1 of 2, checked). A visually hidden legend is acceptable only when a visible heading directly above says the same thing (Settings: Appearance / legend Theme). Give every radio a value.

Motion

None; the dot is the browser's.

Touch

The whole label row is the target and at least 24px tall; options with descriptions are about 40px. Keep 4px between rows, or use cards for a larger target on phones.

Content

  • Option labels are short nouns or noun phrases, parallel in form: Viewer / Owner, Local / Cloud.
  • Descriptions state the consequence: Gives direction, stops work, manages access.
  • Order from least to most powerful or by a natural order (Light, Dark, System); put the default first unless the natural order says otherwise.
  • Legends are nouns: Role, Location, Theme.
