Checkbox

Checkboxes turn independent options on or off, alone or in a group, and take effect when the form is saved.

Overview

Use a checkbox for an option that is independent of the others and is applied with the rest of a form (Save, Apply). Several options that can all be on together form a group in a fieldset. Use a radio group when only one may be on, and a Switch when flipping it takes effect immediately with no save.

The mocks have not needed a checkbox yet; it is part of the core set because the next screens will. The likely first uses are a multi-choice Action filter on the Audit log (today a single select), bulk revoke on Workers (today one row at a time) and opt-ins in Settings' direction defaults.

  • Single, optionally with a description in <small>.
  • Group: a .fieldset with a <legend>, options in .choices (vertical) or .choices--row (wrapping row, for short labels).
  • Select all: a parent checkbox that is indeterminate when some, not all, children are checked.
  • Card (.choice--card): a bordered option that tints when checked, for options with a longer description.

Anatomy

  1. BoxNative checkbox, --size-icon-md (16px), accent-color: --color-accent, nudged --space-0-5 to sit on the first line.
  2. LabelThe whole <label class="choice"> is clickable; --text-body-sm, gap --space-3.
  3. Description (optional)<small>: --text-caption in --color-fg-subtle.

Sizes

Checkboxes have one size: a 16px box (--size-icon-md) on a row at least --target-min (24px) tall; the label is part of the target.

States

The box is the native control coloured with accent-color, so its hover look is the browser's; the card variant adds a hover fill. Focus uses the shared ring; invalid adds a 2px --color-danger-icon outline.

Status
Status
  • Indeterminate is a property, not an attribute: set input.indeterminate = true from script whenever some children are checked. It is announced as mixed.
  • Invalid is rare: only a required acknowledgement can be wrong. Put aria-invalid on the input and the error under the group, linked from the fieldset with aria-describedby.
  • Disabled dims the label to --color-fg-disabled; say why nearby, or hide the option for Viewers.

Responsive behaviour

  • Groups stack vertically at every breakpoint; .choices--row wraps onto new lines below sm instead of shrinking labels.
  • Rows are at least 24px tall with 4px (--space-1) between them in a group; on phones the whole label row is the target.
  • Card checkboxes go full width below sm and can sit two-up in .form-grid--2 from sm.

Theming

accent-color: var(--color-accent) colours the checked box and its tick; the unchecked edge is drawn by the browser from color-scheme, which tokens.css sets per theme. Card colours come from --color-bg-surface, --color-border-default, --color-accent-subtle and --color-accent. In forced colours the native box uses system colours with no extra work.

Accessibility

Role and pattern

Native <input type="checkbox"> in a <label>; groups in <fieldset> with <legend>. Behaviour follows the APG checkbox pattern, including mixed state for select all.

Keyboard

KeyAction
Tab / Shift + TabMoves to each checkbox in turn; every checkbox is a tab stop.
SpaceToggles the focused checkbox. Enter does not toggle; it submits the form.

Focus

The shared ring (2px --color-focus-ring, 2px offset) around the box on :focus-visible. Toggling never moves focus; select all updates the children without moving focus to them.

Labelling

The label text is the name and the <small> description is part of it, so keep descriptions short. The legend names the group (Actions) and is read when focus enters it. A select-all parent says what it selects: Select all workers.

Motion

None beyond the browser's own tick. Card fill changes are instant.

Touch

The label row is at least 24px tall and the whole row toggles, so the target is far larger than the 16px box. Keep 4px between rows; in dense lists, use cards or 44px rows below lg.

Content

  • Say what checking does, positively: Include merged increments, not Don’t hide merged increments.
  • Labels are sentence case without end punctuation; descriptions are one sentence.
  • Legends are nouns: Actions, Status.
  • Never Check this to … or Enable …; the control already says it can be checked.
