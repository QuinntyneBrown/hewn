Avatar

Avatars mark a person with their initials in a small circle: the signed-in Owner in the sidebar, each login on the allow list. They sit beside the name, never instead of it.

WCAG 2.2 AAStatus: stable

Overview

Use an avatar next to a person's login to make lists of people quicker to scan. Hewn has no profile photos yet; avatars are initials. The image variant (a GitHub avatar in <img>) is reserved and shown under Code. Use a status for state, not the avatar's colour.

  • Initials: two letters from the person's name (QB for quinntynebrown, Quinntyne Brown), or from the login's two parts (AO for ama-osei, DP for devon-park).
  • Icon: a system actor, such as Hewn itself merging a pull request.
  • Group (.avatar-group): overlapping avatars for a few people at once.
  • Status dot (.avatar__status): signed in now. Always paired with text that says so.

Anatomy

  1. ContainerA circle (--radius-full), --color-bg-surface-raised with a hairline ring.
  2. InitialsTwo capital letters, semibold, --color-fg-muted.
  3. Status dot8px --color-success-solid with a 2px ring in the surface colour, bottom right.

Responsive behaviour

  • Avatars keep their size at every breakpoint; they do not grow with the layout.
  • In the sidebar user block the avatar stays visible in the collapsed drawer; the name truncates beside it.
  • In row lists below lg the avatar and login share the first cell; the role moves to the right.

Theming

The avatar reads --color-bg-surface-raised, --color-fg-muted and --color-border-default through --avatar-size for its size. Override --avatar-size for a new size rather than writing widths:

.profile-card .avatar { --avatar-size: var(--control-height-lg); }

In dark the raised surface is --palette-slate-850 and the initials --palette-slate-300; the status dot's ring takes the dark surface, so the dot still reads as separate.

Accessibility

Role and pattern

Static content. Next to the person's name the avatar is decorative: aria-hidden="true". Alone (a group, a system actor) it is role="img" with an aria-label naming who. An image avatar is <img alt=""> beside the name or alt="ama-osei" alone. No APG widget pattern; see the APG naming guidance.

Keyboard

KeyAction
TabSkips the avatar; it is never focusable. A clickable profile is a link that contains the avatar and the name.

Focus

None on the avatar itself. When it is inside a link, the link's ring wraps both avatar and name.

Labelling

Never rely on initials alone to identify someone: two people can share them. The name is always next to it or in the label. The status dot has no text of its own; the adjacent text says signed in.

Motion

None.

Touch

Not a target. When an avatar is part of a link, the link (name included) is the target and is at least 24px tall.

Content

  • Initials are two capitals. Use the person's name when known; otherwise the first letters of the login's two parts; otherwise its first two letters.
  • Labels for standalone avatars are the login (ama-osei) or the actor (Hewn (automatic)).
  • Groups name everyone in the label, or the first three and the count (quinntynebrown, ama-osei and 3 others).
