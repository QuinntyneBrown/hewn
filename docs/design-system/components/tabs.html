Tabs

Underline tabs switch between views of one object. Hewn has two kinds that look the same: navigation tabs, which are links to separate pages, and APG tabs, which swap a panel in place.

Overview

Choose the semantics by what activating a tab does, not by how it looks.

KindWhereMarkupPattern
Project sectionsProject header on every project page: Pipeline, Backlog, Designs, Design system, Decisions, Artifacts, Traceability<nav aria-label="Project sections"> of <a class="tab">, current is aria-current="page"Navigation links. Each tab is its own route with its own URL, history entry and <h1>.
Status filterProjects page: All, Running 2, Paused 1, Blocked 1, Idle 1, Complete 1, Cancelled 1, Archived<nav aria-label="Filter by status"> of links with .count, aria-current="page"Navigation links: the filter is in the URL so it can be shared and survives reload.

Use a segmented control instead for two to four options that change a setting (width, theme), and a Select when there are more options than fit on a phone.

Anatomy

  1. Selected tabaria-current="page" or aria-selected="true": default text, medium weight, 2px accent underline.
  2. Tab.tab: label in --text-body-sm, muted, --space-3 inline padding, 44px tall below lg.
  3. Count (optional).count: caption size, subtle, tabular, read as part of the name.
  4. Underline--border-width-thick on the tab, overlapping the list rule by 1px.
  5. List rule.tabs: hairline bottom border; .tabs--flush drops it where the container already draws one.

Both themes

PipelineBacklogDesigns
PipelineBacklogDesigns
  • Active has no separate style; the underline moving is the feedback.
  • Disabled (aria-disabled="true", stays focusable) is for an APG tab whose panel has nothing yet, such as Artifacts before the stage has written any. Navigation tabs are never disabled: a section a role cannot use is not rendered.
  • Overflow: when tabs do not fit, the list scrolls horizontally with the scrollbar hidden; the selected tab is scrolled into view on load.

Responsive behaviour

  • Below --layout-breakpoint-sm (576px): tabs stay one row and scroll sideways (overflow-x: auto, hidden scrollbar); they never wrap or turn into a select. 44px tall. The project header's seven tabs show about four at 360px; the half-visible fifth signals the scroll.
  • sm (576px) to md (768px): more tabs fit; behaviour is the same.
  • From lg (992px): heights drop to 40px (medium) and 32px (small) for pointer use; the project header pads the tab row to --space-8.
  • xl (1200px): unchanged; tabs never stretch to fill the width.

Theming

Tabs read --color-fg-muted, --color-fg-default, --color-accent (underline), --color-border-default (list rule) and --color-fg-disabled. There are no component tokens; to change the underline colour for a surface, override the semantic token in that scope.

/* Tabs on an inverse banner */
.banner--inverse { --color-fg-muted: var(--color-fg-inverse); --color-accent: var(--color-focus-ring); }

In dark the underline uses the lighter dark-theme accent, which keeps its 3:1 against the surface.

Accessibility

Role and pattern

Stage detail follows the APG Tabs pattern with automatic activation: moving focus with the arrow keys selects the tab and shows its panel, because every panel is already loaded with the stage (the log is streaming, runs and decisions are small). Tabs are <button role="tab"> with a roving tabindex, aria-selected and aria-controls; panels are role="tabpanel", aria-labelledby their tab, tabindex="0".

Project sections and status filters are not APG tabs. They are links in a labelled <nav> with aria-current="page"; Tab moves through them and Enter follows them. Giving links role="tab" promises arrow keys and an in-place panel that do not exist.

Keyboard

KeyAction
TabAPG tabs: into the tablist (to the selected tab), then out to the panel. Navigation tabs: through each link in turn.
← / →APG tabs: previous / next tab, wrapping; selects it (automatic activation). Disabled tabs are focused but not selected.
Home / EndAPG tabs: first / last tab.
EnterNavigation tabs: follows the link. APG tabs: no extra effect (already selected).

Focus

The shared ring on :focus-visible, drawn around the tab including the underline area. In a scrolling tab row, a focused tab is scrolled fully into view. After a navigation tab is followed, focus goes to the new page's heading.

Labelling

Every tab list has a name: Project sections, Filter by status (on the <nav>), Stage detail (on the tablist). A count reads as part of the tab name (Running 2); if the number needs context, add it visually hidden (Running, 2 projects).

Motion

Colour changes over --duration-fast and the underline colour over --duration-base; the underline does not slide between tabs. Reduced motion zeroes both.

Touch

44px tall below lg with --space-3 inline padding, so even Log is a 44 × 44px target. Sideways scrolling uses the native gesture; no arrow buttons are needed.

Content

  • One or two words, sentence case, nouns: Pipeline, Design system, Traceability, Runs.
  • Keep the same order everywhere; the project header order follows the pipeline (Pipeline, Backlog, Designs, Design system, Decisions, Artifacts, Traceability).
  • Counts are bare numbers, never in brackets, and only when they help the choice.
  • Do not use tabs for steps in a sequence; that is a Stepper.
