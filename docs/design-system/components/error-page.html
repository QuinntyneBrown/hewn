Error page

Error pages replace a page that cannot be shown (a project that does not exist or cannot be seen, a server failure) while keeping the app shell so people can carry on.

WCAG 2.2 AAStatus: stable

Overview

Use an error page only when the whole page cannot render. The sidebar and top bar stay, so navigation still works; the error takes the main area. When part of a page fails, use an error state in that part; when an action fails, an alert.

  • 404: the project or page does not exist, or belongs to a Hewn the person cannot see. The copy is the same in both cases, so it reveals nothing (L2-039).
  • 500: the server failed to build the page. Show a reference for support and reassure that directions keep running.
  • 403: the person is signed in but their role cannot use this page (a Viewer opening New direction).

Nothing about other projects is shown on purpose.

Anatomy

  1. Code.errpage__code: status code and, for 500, the reference, in mono, subtle.
  2. TitleThe page h1: what happened, in plain words.
  3. TextWhy, what still works, what to do.
  4. ActionsA primary way forward (Try again, Go to projects) and a ghost way back (Dashboard).

Responsive behaviour

  • Base (360px): the content is centred in the main area with 32px top and bottom and 16px side padding; buttons wrap onto two lines if needed.
  • From lg the sidebar returns beside it; the error stays centred in the main area, at least 70% of the viewport tall so it does not sit at the top of an empty screen.
  • The inner column never exceeds 30rem, so lines stay readable on wide screens.

Theming

Error pages use only the canvas and text tokens: --color-fg-default title, --color-fg-muted text, --color-fg-subtle code and reference. No danger colour: a missing page is not an alarm, and the copy carries the meaning.

Accessibility

Role and pattern

A normal page: <main> with one h1, and the HTTP status set for real (404, 500, 403) so assistive tech, crawlers and tests see it. The document <title> starts with the problem: Not found — Hewn. On client-side navigation to an error page, focus moves to the h1. See 2.4.2 Page titled.

Keyboard

KeyAction
TabSkip link, shell navigation, then the error page's actions.
EnterFollows the primary link or activates Try again.

Focus

Focus lands on the h1 (with tabindex="-1") after a client-side route change; on a full page load it starts at the skip link as usual. Retrying keeps focus on the button.

Labelling

The title says what happened (That project isn’t here), not the code alone. The reference is selectable text so it can be copied.

Motion

None, apart from the busy button's spinner, which stops under reduced motion.

Touch

Medium buttons (40px) with 8px between them.

Content

  • Title: what happened, in the person's terms: That project isn’t here, Mission Control hit a problem, You don’t have permission.
  • Reassure about running work: Your directions keep running on their workers; this only affects what you can see.
  • 404 copy is identical whether the project was deleted or belongs to someone else.
  • 500 shows a short reference: 500 · ref 7c2e-91af, and says who to give it to.
  • Actions: one way forward, one way back. No Go home; name the place: Dashboard.
