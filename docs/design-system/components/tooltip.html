Tooltip

A tooltip is a short label or description that appears above a control on hover and on keyboard focus. It names icon-only buttons and explains why an action is unavailable.

WCAG 2.2 AAStatus: stableAPG TooltipCore set (not in the mocks)

Overview

Use a tooltip to name an icon-only Button (Refresh workers), to explain a disabled action (Cancel the running direction first) or to show a keyboard shortcut. A tooltip holds a few words of plain text, never links, buttons or anything the person must read to complete a task. Use an Inline message or the dialog text for anything essential, since touch users never see a tooltip.

  • Label: the tooltip text is the button’s name (aria-labelledby).
  • Description: the button has its own name and the tooltip adds to it (aria-describedby), for example a disabled reason.
  • With shortcut: a .kbd after the text (Resize Spend Shift + arrows).

The mocks use the native title attribute for these 54 times (row actions on Projects, design-state links, width pickers); title never shows on keyboard focus or touch, so the system replaces it with this component.

Anatomy

  1. Tooltip.tooltip: --color-bg-inverse, --color-fg-inverse, --text-caption, padding 6 × 10px, --radius-sm, --shadow-3, max 16rem; 8px above the anchor, centred.
  2. Anchor.tooltip-anchor wraps the control; hover or focus within it shows the tooltip.

Sizes

Tooltips have one size: caption text, 16rem maximum width, wrapping onto a second line if needed.

States

Hidden by default (opacity: 0, no pointer events). Hover shows it after --delay-tooltip (300ms); focus shows it with the same delay; leaving or blurring hides it at once. data-state="open" forces it open for documentation.

Dismissed: Esc hides an open tooltip without moving focus (SC 1.4.13); it stays hidden until the pointer or focus leaves and comes back. Moving the pointer onto the tooltip keeps it open (it is hoverable), though it holds nothing to click.

Responsive behaviour

  • All breakpoints: above the anchor, centred, 8px gap. Keep anchors at least 8rem from the viewport edge (or start-align the tooltip) so it never overflows at 360px.
  • Touch (hover: none): tooltips do not appear on tap; anything a tooltip says must also be available another way (the button’s name, a row note, the dialog that opens).
  • Text wraps at 16rem; it never truncates.

Theming

The tooltip uses the inverse pair (--color-bg-inverse / --color-fg-inverse) so it reads against any surface, with --shadow-3 and --z-tooltip (above dialogs and toasts). The shortcut key inside drops its fill and takes a --color-border-inverse ring.

In dark the inverse pair flips to a light tooltip with dark text, which keeps it the highest-contrast element on the page.

Accessibility

Role and pattern

APG Tooltip: the tooltip has role="tooltip" and an id; the control references it with aria-labelledby (label tooltip) or aria-describedby (description tooltip). It appears on hover and focus, is dismissible with Escape, hoverable and persistent until dismissed (SC 1.4.13). The anchor control keeps focus; the tooltip never takes it.

Keyboard

KeyAction
TabFocusing the control shows its tooltip.
EscHides the tooltip; focus stays on the control.
Shift + TabMoving focus away hides it.

Focus

Focus stays on the anchor control and shows the shared ring; the tooltip is never focusable. Disabled-reason tooltips need the control to stay focusable, so the control uses aria-disabled="true", not disabled.

Labelling

Label tooltips replace aria-label: one source of text, seen and heard. Description tooltips add to a name the control already has (Archive Ledgerline, described by Cancel the running direction first).

Motion

Fades in over --duration-fast after --delay-tooltip; hides with no delay. Reduced motion zeroes the fade but keeps the delay, so a passing pointer does not flash tooltips.

Touch

Tooltips are not a touch affordance. The anchors themselves meet the 24px minimum (row actions are 44px).

Content

  • Label tooltips are the control’s verb and object, sentence case, no full stop: Refresh workers, Copy token.
  • Disabled reasons say what to do first: Cancel the running direction first.
  • At most one short sentence; never repeat a visible label.
