Layout primitives

Five primitives place everything in Hewn: container, grid, stack, cluster and split. They own the space between things, so components only own the space inside themselves.

WCAG 2.2 AAStatus: stableMobile firstToken-driven

Overview

Compose pages from these instead of writing margins on components. The column count, gutter and margin come from tokens that step up at md and lg (see Layout).

  • Container (.container): centres content up to --layout-container-max with --layout-margin on each side. .pad gives only the side margin.
  • Grid (.grid): --layout-columns equal columns (4 / 8 / 12) with --layout-gutter. .grid--cards auto-fills 18rem cards.
  • Stack (.stack): a vertical flow with one gap (16px; --sm 8px, --lg 32px).
  • Cluster (.cluster): a wrapping row with an 8px gap; --lg, --end, --between.
  • Split (.split--*): a stack that becomes a two-column page layout at lg or xl: pipeline stage rail, settings nav, traceability, form with rail, aside.
  • Measures: .narrow (56rem), .form-col (--layout-form-max), .max-measure (--layout-measure, 65ch).

Anatomy

  1. Margin--layout-margin: 16px, 32px from lg.
  2. Column--layout-columns: 4, 8 from md, 12 from lg; equal minmax(0, 1fr).
  3. Gutter--layout-gutter: 16px, 24px from md, 32px from lg.

States

Layout primitives are static; they have no interactive states.

Responsive behaviour

  • Base (0–575px): 4 columns, 16px gutter, 16px margin; every split is one column; clusters wrap.
  • --layout-breakpoint-sm (576px): no grid change; components switch (dialogs centre, toasts move to the corner).
  • --layout-breakpoint-md (768px): 8 columns, 24px gutter.
  • --layout-breakpoint-lg (992px): 12 columns, 32px gutter, 32px margin; the sidebar appears; pipeline, nav, trace and form splits go two-column.
  • --layout-breakpoint-xl (1200px): the aside split and the wider pipeline and form rails.
  • Above --layout-container-max (90rem) the container stops growing and centres.

Theming

Layout has no colour except the rail hairline (--color-border-default). Re-skin spacing by changing the layout tokens, never by overriding the primitives: --layout-columns, --layout-gutter, --layout-margin, --layout-container-max, the rails and the measures. Theme switches do not change layout.

Accessibility

Role and pattern

No roles: layout primitives are plain <div>s. Landmarks (header, nav, main, aside) go on the content, not the primitive. DOM order is reading order: splits put the rail first in the DOM only when it is read first (the pipeline stage list); never reorder with order or row-reverse. The one exception is the dialog footer’s column-reverse on phones, which keeps Cancel first in the DOM and focus order.

Keyboard

KeyAction
TabFollows DOM order through every column, top to bottom, start to end.

Focus

Primitives are never focusable. html sets scroll-padding-top: --layout-topbar-height so the sticky top bar never covers a focused element (SC 2.4.11).

Labelling

Nothing to label. A split’s rail that is a landmark (<aside>) gets an aria-label.

Motion

None. Layout changes at breakpoints are instant.

Touch

Clusters keep at least 8px between targets; at 400% zoom (320 CSS px) every split is a single column and nothing scrolls sideways (SC 1.4.10).

Content

  • Prose stays within .max-measure (65ch); forms within .form-col (42rem).
  • Do not justify text or centre long paragraphs; centre only empty states and short error pages.
