Pipeline strip

The pipeline strip compresses a direction's eleven stages into one bar, so the dashboard shows how far each live run has got at a glance.

WCAG 2.2 AAStatus: stablerole="img"

Overview

Use the strip where many directions are summarised in little space: the dashboard's Live work tile. Each of the 11 segments is one stage, Bootstrap (0) to Increments (10), in order. It is a glance aid: the stage number and name always appear in text beside it, and the full, interactive view is the stage list on the pipeline screen.

Do not use it inside the pipeline screen itself (the stage list already shows every stage), or for progress within a stage; that is a Progress bar.

Anatomy

  1. Done segment.pstrip__seg--ok: one per succeeded stage.
  2. Current segmentThe stage now running (--run), failed (--fail) or paused (--paused).
  3. Pending segmentNo modifier: the track colour.
  4. Track.pstrip: a flex row with a 2px gap; 6px tall; segments share the width equally.

Variants

A strip has no variants of its own; each segment takes one of six looks.

SegmentClassMeaning
.pstrip__seg--okStage succeeded.
.pstrip__seg--runStage running now; pulses.
.pstrip__seg--failStage failed after its retries; direction Blocked.
.pstrip__seg--pausedPaused at a checkpoint (by an Owner, a budget stop, or Stop all workers).
.pstrip__seg--skipSkipped by design (feature directions skip Bootstrap, Designs, Design system, Stack and Scaffold).
no modifierPending: not reached yet.

Sizes

One size: 6px tall (--space-1-5), full width of its container; segments divide the width equally.

States

The strip is not interactive: it has no hover, focus, active or disabled state, and is never a link on its own (the run's name is the link). Its states are the states of the direction, shown in the current segment and repeated in its accessible name.

Both themes

Responsive behaviour

  • The strip is fluid at every breakpoint: 11 equal segments with fixed 2px gaps. At 360px inside a tile each segment is about 26px wide; it never wraps or scrolls.
  • Below sm the dashboard tile stacks name, stage and money above the strip; from lg the tile spans 8 of 12 columns and the strip widens with it.
  • Below 16rem of width the segments get too thin to read; do not place the strip in narrower containers (use the stage text alone).

Theming

Segments read status fill tokens (--color-success-solid, --color-info-solid, --color-danger-icon, --color-warning-solid) and the pending track reads --color-border-default, so they re-tone with the theme and keep 3:1 against the tile surface in both. The skipped segment is an outline in --color-border-strong, so it reads as not part of this run rather than not reached.

Accessibility

Role and pattern

One role="img" element with an aria-label that summarises the run; the segments are presentational spans. No APG pattern applies; see 1.1.1 Non-text content. The adjacent stage text (Stage 10 · Increments) is the primary information, so the strip is never the only carrier (1.4.1).

Keyboard

KeyAction
NoneThe strip is not focusable. Tab moves to the run's name link beside it.

Focus

The strip never takes focus.

Labelling

Group runs of the same status instead of reading 11 stage names: Pipeline: Bootstrap to Estimates succeeded, stage 10 Increments running. Name the current stage and its status every time; give counts for pending or skipped stages.

Motion

The running segment pulses on --duration-pulse. Under reduced motion it holds still at full opacity; the stage text and the spinner's static icon still say it is running.

Touch

Not a target. The tappable run name sits above it with its own 44px row height on phones.

Content

  • Always pair the strip with the stage in words: Stage 3 · Design system, Paused at checkpoint · stage 3.
  • Stage names come from the pipeline, in sentence case: Bootstrap, Idea, Designs, Design system, Stack, Requirements, Scaffold, Detailed designs, User journeys, Estimates, Increments.
  • In the accessible name, number the current stage (stage 10 Increments) and use the same status words as the status badge: succeeded, running, failed, paused, skipped, pending.
