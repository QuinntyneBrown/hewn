Pattern

Data tables and lists

Lists of projects, workers and log entries: dense enough to scan, specific about status, with the object's actions in its row and a mobile layout that stacks instead of scrolling.

Overview

Most of Mission Control is a list of something that is changing: projects at different stages, workers leasing runs, audit entries arriving. The pattern decides which component holds the data, how people narrow it, what they can do to one item, and what happens on a phone.

ComponentUse forMobile strategySeen in
Row listObjects people act on, with a title, status, a few figures and row actionsEach row stacks: title and status, then the stage line, then figures; actions move to their own lineProjects, Backlog, Workers, Users
TableRecords read across columns: logs, runs, matricesLow-priority columns hide (.col-sm, .col-md); their value moves under the main cell as a caption; the rest scrolls inside .table-wrapAudit, Runs, Traceability matrix
ListOne or two lines per item, no columns: events, PRs, files, checksUnchangedDashboard tiles, Artifacts
Description listProperties of one objectPairs stackIncrement, Worker detail

Status is always icon + word; figures are tabular and right aligned; time is relative in lists (4 s ago) and absolute in logs (9 Nov 2026, 14:31:07). Filtering uses Tabs or Select; long ordered sets use Pagination; filters applied as tags use chips.

When to use

QuestionAnswer
Row list or table?If each item is an object you open or act on, a row list. If each item is a record you read across, a table.
Filter tabs or selects?Tabs when there are up to eight mutually exclusive filters worth counting (project status). Selects when filters combine or have many values (Audit: project × action).
Pagination or load more?Pagination for ordered records people come back to (audit, runs). Short lists (projects, workers, under 50) show everything. No infinite scroll: footers and the end of a list must be reachable.
Row actions or a detail page?Up to two frequent actions as icon buttons in the row (Archive, Delete; Revoke; Remove). Everything else on the object's page.
Selection and bulk actions?Not used: Hewn's destructive actions are one object at a time on purpose. Selected rows (aria-selected) only mark the current item in a master-detail view (Backlog, Traceability).
Sorting?Each list has one natural order, stated in the header (sorted by last activity, newest first). Sortable column headers use aria-sort with a button, only where people asked for another order.

  • Column header (.rows__head) is visual only (aria-hidden) and appears from lg; each cell carries its own meaning in text, so the stacked mobile row needs no header.
  • Row title is the only link in the row; the row itself is not clickable, so actions inside it are unambiguous.
  • Row actions are .icon-action buttons whose aria-label names verb and object (Archive Northwind Ops). Disabled ones stay focusable with aria-disabled and the reason in the label and tooltip.
  • Destructive row actions open a dialog (Delete → delete-project); reversible ones act at once and say so (Archive moves the row to the Archived tab, which offers Restore).

Accessibility

Semantics

Row lists are a ul of li.row: each cell's text stands alone (status words, Last sign-in: Never), so the visual column header is aria-hidden. Tables are real tables with a caption (visually hidden when the page title says it), th scope="col", and aria-sort on sortable headers (APG sortable table). Filter tabs are links in a labelled nav; filter selects have visually hidden labels.

Keyboard

KeyAction
TabRow title link, then each row action, row by row. Disabled actions stay in the order so their reason can be heard.
Enter / SpaceActivates a row action; Delete opens its dialog and focus returns to the same row's button.
Shift + Tab after a filterFilters apply on change; focus stays on the control and the result count is announced politely.

Labelling

Row actions name the object: Archive Ledgerline, Remove ama-osei, Restore Saltmarsh Survey; disabled ones add the reason: Delete Ledgerline: cancel the running direction first. Meters in rows are labelled Ledgerline complete and the percentage is printed beside them.

Touch

Row actions are 44px below lg with at least 4px between them; from lg they shrink to 32px where a pointer is expected.

Content

  • Header descriptions state the count and the order: 7 projects · sorted by last activity; captions the order too: Audit log, newest first.
  • Status words come from one vocabulary (Running, Paused, Blocked, Idle, Complete, Cancelled, Archived) and always appear with their icon.
  • Money: dollar sign, two decimals, thousands separator: $612.45, $10,000.00. Percentages without a space: 62%.
  • Relative time in lists with a space before the unit: 4 s ago, 18 m ago, 2 h ago, Yesterday, 3 days ago, then a date (12 Oct). Logs use the full timestamp.
  • An absent value is an em dash (—) in tables, or a word in lists (Last sign-in: Never). Never a blank cell.
