Pattern

Navigation and page structure

One shell everywhere: a sidebar for where you can go, a page header for where you are, project tabs for the views of one project, and a breadcrumb for the way back.

Overview

Mission Control has two levels. The top level is five places in the sidebar (Dashboard, Projects, Workers, Audit, Settings) plus the active directions under them. The second level is a project, whose seven views (Pipeline, Backlog, Designs, Design system, Decisions, Artifacts, Traceability) are tabs in the Project header. Everything else is a dialog over one of those pages, never a third level.

  • Sidebar: primary nav, the New direction call to action, active directions with live status, connection state, Stop all workers, and the signed-in person.
  • Top bar: replaces the sidebar below lg with a menu button that opens the sidebar in a drawer, the wordmark, and the connection dot.
  • Page header: h1, one-line description, page actions. On project pages it is the project header with status, spend, Pause / Cancel and the tabs.
  • Tabs: links to sibling views (aria-current="page"), used for project sections and for list filters.
  • Breadcrumb: only on project pages and below (Projects / Ledgerline, Backlog / Increment 7).
  • Skip link: first focusable element on every page, to #main.

  5. Tabs under the header; the active tab matches the URL.

Back behaviour

  • Breadcrumbs start at the top-level place, not at Dashboard: Projects / Ledgerline. The last item is the current page, not a link.
  • Closing a dialog returns to the page underneath with focus on the trigger; it never adds a history entry.
  • Tabs and filters are links, so Back walks back through them, which is what people expect from URLs.
  • Dead ends offer one way forward: forbidden New direction has Back to projects; the 404 has Go to projects and Dashboard.

Accessibility

Landmarks and headings

Every page has: skip link, aside containing nav aria-label="Primary" (the drawer copy is labelled Primary, menu so the two are distinct), one main id="main", one h1. Project tabs are a nav aria-label="Project sections"; filter tabs a nav aria-label="Filter by status"; the breadcrumb a nav aria-label="Breadcrumb" with an ol. See the APG breadcrumb pattern. Tabs that navigate are links with aria-current, not the APG tabs widget.

Keyboard

Labelling

Active directions announce status in visually hidden text (Ledgerline, Running, 62%). The connection dot in the top bar is role="img" with aria-label="Connection: Live", updated with the state. The wordmark link is Hewn, go to dashboard.

Touch

Below lg nav links, side projects and tabs are 44px (--target-comfortable); from lg they drop to 40px and 32px, where a pointer is likely.

Content

  • Place names are one word, plural for collections: Projects, Workers; singular for the rest: Dashboard, Audit, Settings. The page h1 matches the nav label exactly.
  • Project tabs are nouns named after what the stage produces: Backlog, Designs, Decisions, Traceability.
  • Page descriptions are live facts: 7 projects · sorted by last activity; All workers stopped · 2 directions held at their checkpoints. Separate facts with a middle dot.
  • Filter tabs show the count of each filter beside the name, and no count on All or on tabs that are not counted (Archived).
