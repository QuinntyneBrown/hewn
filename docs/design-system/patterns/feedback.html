Pattern

Feedback and loading

Every action gets an answer in proportion to it: a busy button for a wait, a callout for a failure, a skeleton for a page, a toast for news the person did not ask for.

Overview

Hewn works while nobody watches, so Mission Control's feedback has two jobs: confirm what the person just did, and report what the factory did on its own. The first stays where the person acted; the second goes to the edges of the screen and never steals focus.

The person…FeedbackWhereExample
presses a button that finishes in under a secondNone beyond the result itselfIn placeTheme radio: the page changes theme
presses a button that waits on the serverBusy button, then the resultThe button, then the objectPause → Pausing… → status Paused and the callout Paused by quinntynebrown at 14:29
submits a formBusy primary, then navigate or confirm in placeThe formQueuing direction…; Defaults saved
confirms a dialogBusy danger or primary in the dialog, then close + toast or stripDialog, then pageStopping 3 workers… → strip All workers stopped.
did something that failedDanger callout where they actedForm or dialogHarbor CRM wasn’t deleted
opens a pageSkeleton in the shape of the contentThe region that loadsProjects rows, settings sections
waits on something with a known endMeter or progress bar with numbersThe objectSpend $184.20 of $400.00; Increment 7 of 12
waits on something with no known endSpinner with a sentenceInline with textConnecting to Mission Control… live updates start in a moment.
is told about something they did not doToast (events) or strip (system state)Bottom right / under the top barLedgerline #27 merged; Connection lost.

Components: Button (busy), Alert (callout and strip), Toast, Skeleton, Spinner, Progress bar, Status. How the edge-of-screen messages stack and dismiss is on Notifications.

When to use

IndicatorUse whenDo not use when
SkeletonA page or region is loading and its shape is known (rows, sections, the stage list). Shows within 300 ms.One small value is refreshing; a list is being re-filtered (keep the old rows until the new ones arrive)
SpinnerAn indeterminate wait inline with a sentence or a status (Connecting…, Running), or inside a busy button.A whole page is loading (use a skeleton); the end is known (use a meter)
Meter / progress barThe quantity and its limit are known: spend against budget, percent complete, increments done.The number is a guess; there is no limit
Busy buttonThe person pressed it and is waiting for the server.Background work the person did not start
Optimistic updateThe change is cheap to undo and almost always succeeds (dismissing a toast, reordering tiles in edit layout).Anything that spends money, stops work or deletes

Responsive behaviour

  • Skeletons use the same responsive grid as the content they stand for, so nothing jumps when data arrives: one stacked row per project on phones, the full row grid from lg.
  • Busy labels must fit at 360px: Stopping 3 workers… is the longest in the mocks.
  • Toasts are full width at the bottom below sm and a fixed --layout-toast-width column bottom right from sm; strips are full width under the top bar at every size.
  • Meters inside rows are 3.5rem (.meter--inline) with the percentage beside them at every size.

Accessibility

Announcements

Loading containers set aria-busy="true" and contain a visually hidden sentence (Loading projects) inside an aria-live="polite" region; when content arrives the busy flag clears. Results in place use role="status" (success, info) or role="alert" (failure). Busy buttons keep their focus and name; the outcome is announced by the callout, the toast or the dialog closing.

Keyboard

KeyAction
TabSkeletons are aria-hidden and never focusable; focus skips to real controls.
Enter on a busy buttonIgnored while busy; the button keeps focus.
Enter on Try againRe-runs the load; focus moves to the region's first heading when it succeeds.

Meters

role="meter" with aria-valuenow, aria-valuemin, aria-valuemax and a label (Ledgerline complete, Spend). The visible text carries the same value.

Motion

The skeleton shimmer and status pulse use --duration-pulse; the spinner --duration-spin. Reduced motion sets loops to 0s: skeletons become flat shapes and spinners stand still, while the words (Loading projects, Saving…) still say it is working.

Touch

Nothing in a loading state is a target. Try again is a 40px button.

Content

  • Busy labels are the verb's progressive form plus the object when it helps: Queuing direction…, Stopping 3 workers…, Revoking…, Waiting for GitHub…. Use the ellipsis character.
  • Loading text names the thing: Loading projects, Loading the pipeline. Never Please wait.
  • Results say what is now true and what did not change: Directions already running keep theirs.; Nothing was removed; try again.
  • Known waits give the number and the limit: $200.00 of $250.00. It pauses at $250.00.; promised waits give a time: within 10 seconds, usually within 2 seconds.
  • Never claim success before the server confirms it, except for optimistic, undoable changes.
