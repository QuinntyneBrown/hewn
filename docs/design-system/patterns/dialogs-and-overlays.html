Pattern

Dialogs and overlays

Overlays interrupt. Use a dialog only to confirm something costly or to finish a small task; use a drawer for navigation on phones, a menu for a short list of actions and a tooltip only to name an icon.

Overview

Every Mission Control dialog stands between the person and something that spends money, stops agents or deletes history: stop all workers, cancel a direction, delete a project, revoke a worker, raise a budget, add a login, create a token, update skills. That is the whole list, and new dialogs should be just as rare.

  • Dialog: centred modal from sm, bottom sheet below. role="alertdialog" for destructive confirmations, role="dialog" for small forms.
  • Drawer: the mobile navigation menu, from the start edge. Not used for content.
  • Menu: a short list of actions on one object from a menu button.
  • Tooltip: the name of an icon-only control, on hover and focus. Never content, never interactive.

The page behind a dialog is inert and dimmed by the backdrop (--color-bg-backdrop, --z-overlay); the dialog sits at --z-modal. Only one dialog at a time: a dialog never opens another.

When to use

NeedUseNot
Confirm an action that cannot be undone or spends moneyAlertdialog: consequence, then a danger or primary button named for the actionA browser confirm(); an undo toast for things that cannot actually be undone
Finish a task of one to three fieldsDialog form (Raise budget, Add a GitHub login, New worker token)A new page
Fill in long or several-part inputA page (New direction)A large dialog with scrolling
Show a secret once (worker token)The dialog's success state, with Copy and DoneA toast, which can vanish before it is copied
Navigate on a phoneDrawer with the sidebar insideA bottom sheet or full-screen page
Offer several actions on one objectMenuA row of five buttons

Rules that span them

  • Anatomy order: title, text, optional callout (failures), body (fields or the affected list), footer. Footer: Cancel (ghost) first, the action last, right aligned from sm.
  • The affected list: when an action touches several things, list them (Stop all workers lists the three workers and what each was running).
  • Dismissal: Esc, Cancel and the backdrop close form dialogs; alertdialogs close on Esc and Cancel only, never on a stray backdrop tap. A busy dialog cannot be dismissed until the request settles.
  • After: close and show the result on the page (a strip for Stop all workers, the status for Cancel direction, the row gone for Delete project). The token dialog is the exception: it stays open on success to show the secret once.

Responsive behaviour

BreakpointDialogDrawer, menu, tooltip

Accessibility

Role and pattern

APG alert dialog for confirmations and APG modal dialog for forms and the drawer: aria-modal="true", labelled by the title, described by the text; the page behind is inert. Menus follow the APG menu button; tooltips the APG tooltip.

Keyboard

KeyAction
Tab / Shift + TabCycles inside the dialog only.
EscCloses the dialog, drawer, menu or tooltip and returns focus to the trigger (not while busy).
EnterIn a form dialog, submits from a single-line field.
↑ / ↓Moves between menu items; Home / End jump to the ends.

Initial focus

  • Form dialogs: the first field (New budget).
  • Type-to-confirm: the confirmation field.
  • Plain confirmations (Stop all workers, Cancel direction): the safe button (Cancel / Keep running), so a stray Enter does no harm.
  • Drawer: the close button.

Motion

Dialogs rise in from sm and slide up as sheets below, over --duration-slow with --ease-enter; the drawer slides from the start edge. Reduced motion removes the movement; the dialog simply appears.

Touch

Sheet buttons are full width and 40px tall; the drawer close button is 44px. The sticky footer keeps the action reachable above the on-screen keyboard.

Content

  • Confirmation titles are a question naming the action and the object: Delete Harbor CRM?, Stop all workers?, Revoke build-box-02?, Cancel Ledgerline’s direction?
  • Form dialog titles are an instruction or the thing being made: Raise Kiln Booking’s budget, Add a GitHub login, New worker token.
  • The text says what happens, what is kept and whether it can be undone, with numbers: All 3 online workers halt their active runs within 10 seconds…; Six merged increments stay merged.; This can’t be undone.
  • The action button repeats the verb of the title: Delete project, Stop all workers, Cancel direction. When the action itself is Cancel, the dismiss button becomes Keep running so two Cancels never sit side by side.
  • Failure callouts in dialogs say the object was not changed: Harbor CRM wasn’t deleted, The budget wasn’t changed, Cancel didn’t reach the worker.
